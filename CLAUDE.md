# Repository instructions

This repository contains solutions for the ETH course *Machine Learning in Finance and Insurance*.

## Project structure

- Each numbered project directory contains `data/`, `slides/`, `helpers/`, `output/`, `status.md`, and a main notebook.
- Main notebooks are named `1-main.ipynb`, `2-main.ipynb`, and so on.
- Each project directory contains an `assignment.md` file. Read it before making changes; it is the authoritative source for the required tasks.
- Professor-provided data, slides, and notebook template cells are source material. Do not modify them.
- Put additional project files in `helpers/`.
- Write generated images, analyses, and other deliverables to `output/`.
- After substantial work, update the project's `status.md` with concise, meaningful bullet points.

## Instructions for AI assistants

- Inspect the relevant `assignment.md` and existing notebook before editing.
- Follow the assignment exactly and do not add unrelated work.
- Preserve the notebook structure and all professor-provided content.
- Never delete assignment tasks, questions, or instructional comments from notebook cells.
- Make precise, minimal changes and preserve existing behavior unless the assignment requires otherwise.
- Prefer simple, linear, readable, and reproducible solutions over abstractions or unnecessary complexity.
- Validate code and outputs when practical.
- If requirements are ambiguous, ask for clarification instead of guessing.

## Code and analysis style

- This is university coursework, not production software; prioritize correctness, clarity, and alignment with the assignment.
- Keep implementation code in the relevant notebook cell unless the assignment explicitly requires a separate module.
- Do not introduce unnecessary external functions, classes, or object-oriented abstractions.
- Use small helper functions only when they materially improve readability or avoid meaningful duplication.
- Use clear English for Markdown, comments, outputs, and variable names.
- Add short comments only for non-obvious reasoning, important assumptions, or surprising results.
- Avoid redundant comments, code, and output.

## Response style

- Be concise, direct, and schematic.
- Use simple English and prefer bullet points.
- Include only the explanation needed to make the result clear.
- Do not repeat information unnecessarily.
